# wasl-ops

Operations repo for the Wasl (وصل) migration off Lovable + hosted Supabase onto self-hosted
PostgreSQL. It holds no application code — the three app repos are `wasl-api`, `wasl-web`
and `wasl-mobile`.

## Layout

| Path | What it is |
| --- | --- |
| `MIGRATION-LOG.md` | Step-by-step log of the migration, newest at the bottom. |
| `docs/PLAN.md` | The approved migration plan and its phases. |
| `docs/PHASE0.md` | How to dump the live Lovable Cloud database (must happen before any schema work). |
| `docs/RUNBOOK.md` | Day-to-day local stack operations. |
| `docs/schema-inventory.{md,json}` | Inventory of the live schema, generated by `scripts/schema-inventory.mjs`. |
| `docs/legacy-functions.sql` | The original Supabase RPCs, kept as the reference for the API's authorization rules. |
| `db/` | Baseline build: the stale Lovable migrations, the reconstructed missing objects, and the transform into the new schema. |
| `scripts/` | Dump, schema-diff and smoke-test scripts (`smoke-{auth,orders,admin,web}.sh`). |
| `tools/` | Local PostgreSQL 17 via `embedded-postgres` (`pg.mjs`) plus `psql`/`pg_dump` wrappers, used because Docker is unavailable on the dev machine. |

## Local stack

```bash
node tools/pg.mjs start        # PostgreSQL 17 on 127.0.0.1:55432
export PATH="$PWD/tools/bin:$PATH"   # psql, pg_dump, pg_restore
bash db/build-baseline.sh      # rebuild the baseline schema from db/
```

Then run the API from `wasl-api` (`node dist/main.js`) and the smoke scripts against it.

Real dumps, bucket downloads and credentials are gitignored and must never be committed.
